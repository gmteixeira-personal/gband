## Context

See proposal.md for the motivation. This change starts after window-names is archived. The state it builds on:

- window-names draws the shown name on the top border of each tiled and floating window that runs a program, in `draw_tile` (`crates/client/src/render.rs`).
- window-names regenerated every reference under `tests/lua/screenshots/`, and presumably `examples/plugins/*/tests/screenshots/`. It also updated any end-to-end assertion that reads a tile's top border row.
- The `gband test` runner builds each case's environment in `crates/harness/src/case.rs`, which already sets `GBAND_ANIMATIONS=off`. gband's own end-to-end tests build theirs in `crates/harness/src/env.rs`, which sets `SHELL=/bin/sh`.
- `crates/client/src/animation.rs` reads `GBAND_ANIMATIONS` once at start, logging a warning for an unknown value. That is the precedent for an environment switch that tests set.
- `g.start` already saves per-case presets that keep references stable, such as `theme`.

## Goals / Non-Goals

**Goals:**
- A screen reference shows a title only when its case asks for one.
- The references return to their content before window-names, so this change's diff is a pure revert of title rows. That makes it easy to review.

**Non-Goals:**
- Masking titles at compare time. It would hide a regression in the border under a title.

## Decisions

### An option for users, an environment variable for tests
Users turn titles off with `gband.set({ window_titles = false })`, which reloads like every other option. Tests cannot use the option: most cases run the default configuration with no `user/init.lua`, and writing one would replace the defaults under test. An environment variable reaches the client in every case with no file. `GBAND_ANIMATIONS` already sets the pattern of one read at start, `off`/`on`, and a warning otherwise.

`off` wins over the option, so a case that loads a configuration setting `window_titles = true` still draws no title unless the case asks for titles.

Alternatives considered:
- *A saved file under `user/`, as `keystyle` and `theme` are.* That is a settings-window preference, saved by the settings window. Titles are not a settings row.
- *The environment variable only, with no option.* Users would have no supported way to drop titles from their own configuration.

### `g.start{ window_titles = true }` over `env = { GBAND_WINDOW_TITLES = false }`
`env` removal already works, but a named field documents intent, matches `keystyle` and `theme`, and keeps the variable an implementation detail of the runner.

### gband's own end-to-end tests share the default
`TestEnv` sets `GBAND_WINDOW_TITLES=off` in its base environment, beside `SHELL=/bin/sh`. A test about titles removes it through the existing per-command environment hook, `adjust`, in `crates/harness/src/terminal.rs`. Only `tests/window_names.rs` does.

### References restored, not regenerated by hand
Regenerating with `GBAND_UPDATE_SCREENSHOTS` under the new default reproduces each reference without its title row. Each regenerated file is compared with its content at the commit before window-names merged. Every difference other than the key list's `N` line, and lines that moved because of it, is a defect in this change.
