- [ ] 2.4 Implement `ConfigError` in `crates/lua/src/error.rs`, normalising `mlua` syntax, runtime and callback errors and Rust-raised validation errors into `path:line: message`, with locations from `inspect_stack(1)`. - [ ] 2.5 Implement the `gband` table in `crates/lua/src/api.rs`: `set`, `bind`, `unbind`, the `action` table of `LuaAction` userdata with `__call`, and `spawn`. Verify with unit tests for every "Bind and unbind keys", "Action values", "Spawn a program" and "Binding functions" scenario that needs no client
- [ ] 2.6 Write `crates/lua/src/defaults.lua` with today's prefix, options and the 19 prefix bindings, using only the public API. Implement `load(path) -> Result<Config, ConfigError>`, evaluating `defaults.lua` then `init.lua` in a new `Lua` and treating a missing file as no error. Verify with a test that evaluates `defaults.lua` alone and compares its options and bindings, entry for entry, with the client-attach default table, and a test that `gband.action` holds exactly the 19 Lua names of the actions capability
- [ ] 2.7 Implement the configuration path, honouring an absolute `XDG_CONFIG_HOME` and otherwise falling back to `~/.config`. Implement the watcher, which observes the directory of `init.lua`, or its parent until that directory exists, filters by file name, debounces 100 ms and reloads on a blocking thread, delivering `Result<Config, ConfigError>` over a channel. Verify with unit tests for the path rules, and a test that writing, renaming over and deleting a temporary `init.lua` each deliver a reload within one second
