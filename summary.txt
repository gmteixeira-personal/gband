# Rust terminal multiplexer: design summary

## Goals
- Terminal multiplexer (like tmux / zellij / herdr), written in Rust, scripted in Lua.
- niri-style layout: workspaces, each an infinitely scrolling horizontal ribbon of columns.
- Sessions stay alive when clients detach or the terminal crashes.
- Native agent awareness (Claude Code, Codex, etc.) with notifications.
- Highly configurable.
- Remote use is important: client can run locally (connecting to a remote server) or on the remote machine.

## Non-goals / decisions
- Not a terminal emulator app (no window, fonts, GPU). Runs inside foot, Ghostty, etc.
  Still needs an internal emulation layer per pane (vt100 grid) — every mux has one.
- Pane processes do NOT survive a server crash (neither do herdr's or zellij's).
  Instead: snapshot layout + relaunch agents via their native resume.
- Keep PTY ownership behind an internal trait so live handoff / holder processes can be added later.

## Architecture: server owns content, client owns presentation (hybrid)

### Server (one per session)
- Pane host: spawns programs in PTYs (portable-pty), one vt100 grid per pane.
  Sets RMUX_PANE / RMUX_SOCKET env vars. Detects foreground process via tcgetpgrp + /proc/<pid>/cmdline.
  Panics caught per pane.
- Core (pure logic, no I/O): workspaces, ribbon of columns, column widths, focus,
  per-pane agent state machine. Changes happen via actions; every change emits events.
- Behavior Lua: keybindings for session actions, rules, agent adapters, spawn defaults.
  Runs on its own thread, talks to core via messages.
- Services: agent events (kept pending if no client attached), persistence snapshots.
- Decides everything that affects programs: PTY sizes, pane/column widths, input routing.

### Client (same binary, local or remote)
- Raw mode, crossterm for input, reports size + capabilities (kitty keyboard etc.) on attach.
- Keeps its own vt100 grid per pane, fed by diffs from the server.
- Composes and renders locally with ratatui + tui-term: camera, animations, chrome.
- Resolves keybindings locally:
  - View actions (camera scroll, viewed workspace, on-screen focus) run instantly in the client.
  - Session actions (new/close pane, resize columns) go to the server.
  - Program keystrokes go to the server, into the PTY.
- Presentation Lua: theme, column headers, status bar, badges, view keybindings.
- Notifications: desktop (notify-rust) when running locally; OSC 9 / 777 / 99 when over SSH.
- Animations: full niri-style locally, reduced/off over SSH (config default: auto).

### Transports
- Unix socket (client on same machine as server).
- SSH proxy: `ssh host yourmux proxy` bridges stdio to the remote socket.
- One Transport trait, two implementations.
- Remote modes:
  - Local client → remote server: `yourmux attach <host>` (smooth animations, local notifications).
  - Client on remote host: SSH in, `yourmux attach` (zero setup, tmux-like).
- Future: one client connected to several servers, combined agent view.

### Protocol
- Version exchange on connect; keep messages additive.
- Client: postcard. CLI + event stream: JSON.
- Sync like mosh: server sends diff from the client's last acked state to current
  (vt100 state_diff), not a backlog. Full snapshot on attach/reconnect.
- Heartbeats, auto-reconnect with resync, visible "disconnected" state.

## Layout model (niri)
- Session → workspaces (vertical) → infinite strip of columns → panes stacked in a column.
- Column widths as proportions (1/3, 1/2, 2/3) or fixed cells.
- Offscreen panes keep their size (no SIGWINCH thrash).
- Camera per client; center-on-focus or "just visible" policy, configurable.
- Animations: cell-granular steps. For resizes, animate visually (clip/pad old grid),
  resize the PTY once at the end; debounce held resize keys (~100 ms).

## Agent awareness
Signal sources, most → least reliable:
1. Agent hooks: e.g. Claude Code hooks (Notification, Stop, UserPromptSubmit) call
   `yourmux agent-event <state>`; forward hook JSON (session id, cwd).
   `yourmux install-hooks claude` can write the config.
2. Escape sequences: bell, OSC 9 / 777 / 99 from the pane.
3. Process detection: foreground process name.
4. Heuristics: output quiescence, screen prompt patterns.
- Per-pane state machine: none → working → waiting → done / error.
  Notifications fire on transitions; higher-reliability sources override lower ones.
- Adapters defined in Lua so new agents need no recompile.
- UI: column badges, edge indicators for offscreen columns ("2 waiting ←"),
  per-workspace counts, "jump to next waiting agent" binding.
- Suppress notifications for the focused pane of an active client.

## Configurability
- Rust core small; defaults.lua built on the same public API users get.
- Everything is an action (keys, mouse, CLI, Lua, command palette).
- Key tables / modes + which-key popup.
- niri-style rules: match process / cwd / title / agent → width, workspace, notify, adapter.
- UI as Lua render functions, called on events and cached.
- Notification pipeline: event selection → filtering → delivery, all configurable.
- External scripting: `yourmux msg <action>` + JSON event stream (for waybar, scripts).
- Safety: typed validation (mlua serialize + serde) with file/line errors; hot reload (notify);
  keep last good config on error; Lua instruction-count hook for runaway scripts;
  per-project .yourmux.lua requires explicit trust.
- Ship defaults good enough for an empty config.

## Persistence
- Periodic snapshot: layout, cwd, argv, agent session ids (+ original launch flags).
- After server crash: rebuild ribbon, relaunch agents with resume
  (e.g. `claude --resume <id>`), shells fresh.

## nvim compatibility checklist
- Input encoding respecting per-pane modes (application cursor keys).
- Kitty keyboard protocol (crossterm PushKeyboardEnhancementFlags; detect with
  supports_keyboard_enhancement per client).
- Cursor shape passthrough (DECSCUSR) for focused pane.
- Undercurl / underline colors (verify vt100 + ratatui support).
- Focus events, bracketed paste, mouse with coordinate translation, OSC 52 clipboard.
- Synchronized output when the outer terminal supports it.
- TERM=tmux-256color (or xterm-256color), COLORTERM=truecolor in panes.
- Test with :checkhealth, insert-mode cursor, <C-i> vs <Tab>, diagnostics, mouse, yank, big paste.

## Crates
- Terminal: portable-pty, vt100 (upgrade path: alacritty_terminal headless), tui-term, ratatui, crossterm
- Async/protocol: tokio, serde, postcard, serde_json
- Lua: mlua (lua54 or luajit, vendored, serialize, async, send)
- CLI: clap
- System: rustix (process, termios)
- Notifications/config: notify-rust, notify, directories
- Logging/errors: tracing, tracing-subscriber, tracing-appender, thiserror, anyhow
- Check tui-term's pinned vt100/ratatui versions match.
- Keep the vt100 dependency behind a small internal trait.

## Workspace layout
- core: layout, ribbon, agent states (heavily unit tested, no I/O)
- protocol: messages, versioning
- server: pane host, services, behavior Lua host
- client: transports, rendering, presentation Lua host
- lua: shared mlua bindings / API
- yourmux binary with subcommands: server, attach, msg, agent-event, proxy, install-hooks

## Build order
1. Single pane end to end over a local socket: server, PTY, vt100, client, attach/detach.
2. Multiple panes in one column.
3. Ribbon + camera, then workspaces.
4. Lua (behavior + presentation), rules, keymaps.
5. Agent detection + notifications.
6. SSH proxy transport, reconnect/resync.
7. Persistence + agent resume.

## References
- herdr (ratatui + tui-term + vt100 + crossterm + portable-pty; agent detection, session restore, live handoff)
- zellij (own grid on vte; session resurrection)
- wezterm (mux server, Lua config, SSH domains)
- tmux (extended-keys, key tables)
- niri (layout model, window rules, live config reload, `niri msg` event stream)
